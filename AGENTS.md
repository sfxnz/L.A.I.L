## Coding rules (all coding work)

Load the `karpathy-coding-guidelines` skill. Four defaults:

- **Think first** — state assumptions; ask on real ambiguity; don't pick an interpretation silently.
- **Simplicity** — minimum code that solves the problem; no speculative features or abstractions.
- **Surgical** — every changed line traces to the request; no drive-by refactors or reformatting; clean up only your own orphans.
- **Verify** — define the check up front; run tests/build and show real output before claiming done.

## Repo notes

- Never re-track runtime state: `data/*.sqlite`, `data/multinode_serve.json`, `apps/web/next-env.d.ts` are gitignored on purpose — they dirty every serve/eval run.
- Serve config is generated by the placement engine in `packages/serve-engine/app/services/autoconfig.py`; add future model recipes to `data/serve_overlays.json` rather than hardcoding.
- A headless multi-node TP worker reports state `serving_worker` (no `/v1/models` endpoint by design) — treat it as serving in any UI check.
